## 5. 兼容性与版本要求（重要）

- **目标平台**：微信小程序（MP-WEIXIN）为首要目标，使用 `uni-app` 构建以兼容多端，但需区分平台差异。
- **推荐 uni-app / HBuilderX 版本**：使用支持 Vue3 的 uni-app 版本（HBuilderX 或 uni-cli 与 Vue3 支持），并在项目 README 中锁定最低版本号（如：uni-app >= 3.x，HBuilderX >= 3.x，视具体发布时间而定）。
- **Vue 版本**：Vue3（Composition API）——建议在新功能中优先使用 Composition API，便于模块化与可测试性。
- **状态管理**：推荐使用 Pinia（对 Vue3 原生支持），若当前使用 Vuex，建议在新模块中使用 Pinia 并逐步迁移。
- **微信云开发（wx.cloud）**：
  - 微信云开发 API 仅在 `MP-WEIXIN` 平台可用；在 uni-app 中必须通过条件编译（#ifdef/#endif）或抽象层处理调用。
  - 云函数 Node 运行时需与云端环境兼容（在文档中标注云函数运行时 Node 版本要求，例如 Node 14/16），避免使用本地二进制原生模块。
  - 建议将与云相关的所有调用封装到 `services/cloud/` 或 `services/api` 层，并在实现中使用平台判断。
- **H5 / App 平台差异**：
  - H5 与 APP 平台可能没有 `wx` 全局对象；所有云相关、平台特定能力必须通过抽象适配层（详见下一节）处理。
  - 在文档中维持“兼容矩阵”（platform × feature）表格，明确哪些功能仅在微信小程序可用。

## 6. 云开发抽象层与约定（示例）

- **目的**：将平台特有 API（如 `wx.cloud`）封装，以便单元测试、H5 运行和未来迁移到 uniCloud 或其他后端时最小改动。

示例目录：
```
src/
 ├─ services/
 │   ├─ cloud/
 │   │   ├─ index.ts        # 对外暴露统一接口（init, callFunction, db 等）
 │   │   ├─ wx.ts           # 微信小程序实现（仅 MP-WEIXIN）
 │   │   └─ mock.ts         # H5 / 开发环境的 mock 实现
```

示例接口（伪码）：
```ts
// src/services/cloud/index.ts
export async function initCloud() {
  // #ifdef MP-WEIXIN
  return await import('./wx').then(m => m.initCloud())
  // #endif
  // #ifndef MP-WEIXIN
  // return mock init or no-op
  // #endif
}
```

约定：
- 所有云交互必须通过 `services/cloud` 暴露的函数完成，页面或组件不直接引用 `wx.cloud`。
- 云函数返回值要有统一包装（{ success: boolean, data?, error? }），避免页面层处理过多异常分支。

## 7. 模块化开发规范（文档驱动）

- **模块边界**：每个业务模块（如 `phonics`, `game/puzzle`, `parent`）应包含自己的 pages、components（只在本模块内复用）、services（后端/云调用）、assets、tests。

建议的模块化目录结构：
```
src/modules/
 ├─ phonics/
 │   ├─ pages/
 │   ├─ components/
 │   ├─ services/
 │   ├─ assets/
 │   └─ index.ts   # 导出本模块路由与初始化逻辑
```

- **组件复用策略**：
  - 公共组件放 `src/components/`，模块内私有组件放 `src/modules/<module>/components/`。
  - 组件需带 `README.md`（props/事件/示例），并在 `开发文档` 中记录契约。

- **接口与服务**：
  - 所有后端交互走 `src/services/*`，并提供单元测试替身（mock）。
  - 服务方法签名需有明确的类型注释（建议逐步引入 TypeScript）。

- **模块提交与验收（Doc-driven）**：
  - 新增模块必须同时提交：页面/组件代码 + 对应模块 README（功能点、路由、素材、接口契约）+ 单元/集成测试（如适用）。
  - PR 模板必须包含“是否更新开发文档”选项。功能未在文档中先声明，代码不可合并。

  - [ ] 云调用已封装在 `services/cloud`
  - [ ] 新增组件已添加使用示例
  - [ ] 版本/依赖变更已记录在 `manifest.json` 或 README
