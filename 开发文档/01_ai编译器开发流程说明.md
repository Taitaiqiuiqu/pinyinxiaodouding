# AI编译器开发流程说明

## 1. 文档目的
本文件用于告知 AI 编译器（如 Cursor / Copilot / Gemini / ChatGPT Code 模式）在开发儿童汉语拼音学习小程序时，应遵循的整体开发流程、阶段划分与输出物要求。

---
## 2. 开发总体流程

### 阶段一：需求理解（Requirement Understanding）
- 输入文档：
  - 《小程序功能说明与用户流程》
  - 《儿童分龄拼音能力目标说明》
- AI 编译器任务：
  - 拆解页面列表
  - 明确不同年龄段的功能开关
  - 标注哪些功能为 MVP 必需，哪些为扩展功能

### 阶段二：架构生成（Architecture Generation）
- 输出内容：
  - 前端页面结构（pages）
  - 公共组件（components）
  - 素材目录（assets）
  - 状态管理（如全局年龄、家长监管状态）

### 阶段三：功能模块实现（Feature Implementation）
- 优先级顺序：
  1. 年龄收集 + 家长监管
  2. 在线课程（分龄开放）
  3. 基础跟读模块
  4. 游戏训练模块
  5. 正向 / 失败反馈

### 阶段四：素材接入（Assets Binding）
- AI 编译器需根据《素材规范说明》：
  - 正确引用角色图
  - 在对应节点播放音频
  - 控制动画与音频的先后顺序

### 阶段五：验收与可扩展性检查
- 确保：
  - 新增拼音 / 新增课程无需改动主流程
  - 素材缺失时有兜底逻辑

---
## 3. AI 编译器行为约束
- 不生成成人向文案
- 不生成复杂菜单（3-8 岁不可理解）
- 所有交互必须“可被语音引导”

---
## 4. 最终输出物
- 可运行的小程序代码
- 清晰的目录结构
- 所有功能点与文档一一对应
 
---

## 5. 兼容性与文档驱动约束（新增）

- **模块 README 要求**：AI 编译器在生成或修改任一业务模块时，必须同时输出符合 `开发文档/module_README_TEMPLATE.md` 模板的模块 README，包含页面列表、组件契约、服务接口与兼容性说明。
- **兼容性引用**：AI 生成的代码须遵循 `开发文档/compatibility.md` 中的兼容矩阵；若某功能只能在 `MP-WEIXIN` 可用，AI 编译器应输出替代实现或明确注释并使用条件编译符号（#ifdef/#endif）。
- **云调用封装**：AI 不应直接在页面层生成对 `wx.cloud` 的直接调用；必须通过 `src/services/cloud` 的抽象接口调用云能力，并生成相应的 mock 实现以支持 H5 本地预览。
- **生成物验收清单**：每次输出应包含：
  - 代码（pages/components/services）
  - 模块 README（模板填充）
  - 兼容性声明（平台支持说明）
  - 简单的运行/验证步骤（如何在 MP-WEIXIN 与 H5 运行）
